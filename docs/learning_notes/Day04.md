# 一、Python 主线学习记录


## 1. Python 函数基础


## 1.1 函数作用

函数用于将具有独立功能的代码进行封装。

作用：

- 提高代码复用性
- 降低程序复杂度
- 提高代码维护能力


理解：

程序不应该把所有逻辑全部写在主流程中。

应该：

```
主流程

↓

调用功能函数

↓

完成具体任务
```


---

## 1.2 函数定义与调用


学习：

函数定义：

```python
def function_name():
    pass
```


函数定义后不会自动执行。

需要通过调用：

```python
function_name()
```


执行。


理解：

```
定义函数

↓

保存功能

↓

调用函数

↓

执行逻辑
```


---

# 2. 函数参数学习


## 2.1 参数作用


函数参数用于接收外部传入的数据。


例如：

```
add_task(task)
```


调用：

```
add_task("学习Python")
```


Python会自动创建函数内部变量：

```
task = "学习Python"
```


理解：

函数参数本质：

> 在函数执行时创建局部变量，用于接收外部数据。


---

## 2.2 参数设计原则


函数需要什么数据，就传入什么参数。


例如：

错误：

```
show_task(user_input)
```


如果函数内部没有使用：

```
user_input
```

则该参数没有意义。


正确设计：

```
show_task()
```


设计原则：

不要为了添加参数而添加参数。


---

# 3. return 返回值


学习：

return用于向调用者返回结果。


理解：

print：

```
给用户查看
```


return：

```
给程序继续处理
```


例如：

```
函数判断结果

↓

return True / False

↓

主程序根据结果决定下一步
```


---

## return执行特点


return执行后：

- 当前函数立即结束
- 后续代码不会执行


理解：

return不仅用于返回数据，也用于控制函数流程。

# 5. 变量作用域（Scope）


学习：

变量根据定义位置具有不同作用范围。


## 局部变量


定义在函数内部。

特点：

- 只在函数内部有效
- 函数结束后生命周期结束


---

## 全局变量


定义在函数外部。

特点：

- 可以被多个函数访问
- 过度使用会增加程序维护难度


工程实践：

推荐：

```
参数传入

+

return返回
```

保持数据流清晰。

# 5. onclick事件绑定


正确：

```
button.onclick = addTask;
```


表示：

点击按钮后执行函数。


错误：

```
button.onclick = addTask();
```


表示：

页面加载时立即执行函数。


理解：

事件绑定需要传递函数本身，而不是执行结果。

# 三、遇到的问题


## 1. 函数参数是否自动生成变量


问题：

调用函数时：

```
add_task("学习Python")
```

参数 task 是否自动生成变量？


解决：

理解：

函数参数会在执行时创建局部变量。


执行过程：

```
调用函数

↓

创建参数变量

↓

执行函数内部逻辑
```


---

## 2. show_task是否需要参数


问题：

```
show_task(user_input)
```


解决：

分析函数内部实际使用的数据。


如果函数直接访问任务列表：

```
tasks
```

则不需要额外传入：

```
user_input
```


---

## 3. check_task是否应该直接输出错误


问题：

函数内部直接：

```
print("任务不能为空")
```


解决：

改为返回判断结果：

例如：
```python
def check_task(task):
    if task=="":
        return False
    return True
    # 只判断不执行，不要让函数承担太多职责，即又判断又输出，又控制程序退出 
while True:

    user_input = input("请输入任务:")

    if user_input == "exit":
        break

    elif user_input == "list":
        show_tasks()

    elif check_task(user_input):
        add_task(user_input)
    # 函数返回True则执行，False则不执行
    else:
        print("任务不能为空")
```


由主程序决定如何处理。

- 用户操作会触发对应函数。
